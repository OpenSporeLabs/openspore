# tests/

Test-fixture + differential-test system for the `tools/spore/` format readers
(DBPF, RW4, GMDL). Python 3.10+ stdlib only — `unittest`, no pytest, no
runtime dependency on SporeModder-FX.

## Run the suite

From the repo root:

    python3 -m unittest discover -s tests -t . -v

The suite is fully synthetic (see below) and is the CI-safe default.

## Fixtures (synthetic, deterministic)

`tests/fixtures/` contains three small binary fixtures generated by
`tests/fixtures/gen_fixtures.py` (pure Python, no timestamps/randomness):

| fixture | content |
|---|---|
| `mini_package.dbpf` | DBPF v3, 3 records: `TSTX` (uncompressed, 16B), `QFS1` (QFS/RefPack-compressed, 412B payload / 421B on disk), `RAWB` (uncompressed, 64B) |
| `mini_rw4.rw4` | RW4 container: header + manifest + type table + 3 sections — BaseResource (12B), Raster (4x2 texture, 8 texels), Mesh (4 vertices, 6 u16 indices) |
| `mini.gmdl` | GMDL version 8: 1 referenced file, 1 mesh (153 u16 indices), bbox + radius, 1 vertex descriptor (POSITION/TEXCOORD), 1 vertex buffer (50 verts, 16B stride) |

Re-running the generator over existing fixtures fails loudly if the bytes
would differ, keeping the committed fixtures reproducible. Delete a fixture
and re-run to regenerate it:

    python3 tests/fixtures/gen_fixtures.py

The generator also contains a small QFS *compressor* (inverse of
`dbpf.qfs_decompress`) so the compressed record is genuinely round-tripped by
the tool's decompressor, not just stored raw.

## Test style

`test_formats.py` compares parsed structures (dicts) against inline expected
dicts of *semantic* fields — never raw bytes. On mismatch it prints a compact
expected-vs-actual diff. Tests that exercise the CLI run the tools as
subprocesses and assert on their printed lines.

## Real-asset differential mode (opt-in)

    python3 tests/diff_real.py

Only runs if `SPORE/` (and the referenced package) exists locally — e.g. a
GOG install. It extracts one small known record
(`Spore_Content.package`, GMDL 0x00e6bce5, 80B) into
`/tmp/opencode/spore/out/`, parses it with the committed tools, and compares
the semantic fields against `tests/expected/real_gmdl_1006.json`.

- **No `SPORE/`** → prints a clear message and exits 0 (fresh checkout / CI).
- **Missing expectation file / changed package** → exits non-zero with guidance.
- Re-record the expectation after a known-good local check:
  `python3 tests/diff_real.py --record`

The expectation file stores semantic fields only (type IDs, sizes, counts,
rounded bounds) — never asset bytes — so it is safe to commit.
