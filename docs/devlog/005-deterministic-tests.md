# 005 — Deterministic tests: pinning the formats down

## 2026-09-20, evening (commit `9f073dd`, 18:59)

State of play: the format tooling from [chapter 004](004-format-tooling.md) had
landed 36 minutes earlier (commit `8a2caf5`, 18:23). Three parsers now lived in the
repository — `dbpf.py`, `rw4.py`, `gmdl.py` — and had been validated against the real
~5 GB GOG install: type histograms over all seven packages, record extraction with QFS
decompression, and GMDL v8 samples walked to the exact file size. But none of that was
*protected*. The parsers were as fragile as the `/tmp` code they had been promoted from:
a refactor of `dbpf.py`'s QFS path, a wrong field offset in `gmdl.py`'s vertex-descriptor
walk, a silent break in `rw4.py`'s base-resource indirection — none of it would have been
caught, because there was no test that ran the tools. And the data that had proven them
correct could never become that test: the packages are proprietary and git-ignored, and
extracted samples sit in git-ignored `out/` directories that vanish with them. The
decision of the evening, committed at 18:59, was to build the regression surface on data
the project generates itself, with one small committed semantic anchor to the real asset
pipeline. That is commit `9f073dd`, "Add synthetic format fixtures, semantic-snapshot
tests, and opt-in real-asset differential" — 12 files, 712 insertions, 3 deletions.

## Why synthetic deterministic fixtures

The core decision fell out of two constraints.

First, the legal boundary from chapter 004 is absolute: the repository is the public
artifact, and **no proprietary bytes ever enter it** — no `.package` record, no rw4/gmdl
sample, no extracted asset. Any test that reads from `SPORE/` or from `out/` is
unrunnable on a fresh checkout, and in CI it would be reading data that does not exist
there by definition.

Second, a test suite is only as reproducible as its inputs. So the committed suite runs on
fixtures the project generates itself. `tests/fixtures/gen_fixtures.py` (216 lines) is
pure Python stdlib — no timestamps, no randomness, no environment read:

- Re-running it over existing fixtures **fails loudly** (`write_if_identical` exits with a
  FATAL message) if the regenerated bytes differ from the committed ones. The three
  fixtures are therefore pinned reproducible artifacts, not disposable scratch files: the
  generator is the only thing allowed to write them, and it verifies identity.
- Delete a fixture and re-run to regenerate it byte-for-byte.

The three fixtures:

| fixture | on disk | content |
|---|---|---|
| `mini_package.dbpf` | 685 B | DBPF v3, 3 records: `TSTX` uncompressed (16 B); `QFS1` genuinely QFS/RefPack-compressed (412 B payload / 421 B on disk); `RAWB` uncompressed (64 B) |
| `mini_rw4.rw4` | 392 B | header + manifest + type table + 3 sections — BaseResource (12 B), Raster (4×2 texture, 8 texels), Mesh (4 vertices, 6 u16 indices) |
| `mini.gmdl` | 1266 B | v8: 1 referenced file, 1 mesh (153 u16 indices), bbox + radius, 1 vertex descriptor (POSITION/TEXCOORD), 1 vertex buffer (50 verts @ 16 B stride) |

The non-trivial piece is the generator's small **QFS compressor** — a greedy encoder for
the QFS token grammar (big-literal tokens of up to 112 bytes; small tokens for runs of
identical bytes), written as the *inverse* of `dbpf.py`'s `qfs_decompress`. This matters
because the compressed record is not a canned blob: `gen_fixtures.py` encodes the
412-byte payload, stores the 421-byte result in the package, and the test then runs it
back through the committed decompressor and asserts byte equality with the original
payload. That inversion is the strongest form the validation can take — encoder and
decoder are independent directions of the same spec, so a bug in either one breaks the
round trip. The uncompressed records (`TSTX` 16 B, `RAWB` 64 B) pin the non-compressed
path of the index walk.

## The 15 tests

`tests/test_formats.py` (273 lines), Python 3.10+ stdlib only — `unittest`, no pytest, no
runtime dependency on SporeModder-FX:

| format | test | what it pins |
|---|---|---|
| DBPF | `test_header` | 96-byte header fields: magic `DBPF`, major 3, idxCount 3, idxSize 84, idxOffset 96, fileSize 685 |
| DBPF | `test_index` | all 3 index records: type/group/instance IDs, offsets, csize/msize, comp flag |
| DBPF | `test_type_id_decode` | 32-bit binary IDs decode to 4CCs `TSTX`/`QFS1`/`RAWB` |
| DBPF | `test_decompressed_content_equality` | every extracted record equals its generator payload byte-for-byte — the QFS record *through* the committed decompressor |
| DBPF | `test_deterministic_extraction` | two full CLI extractions into separate temp dirs produce identical file sets and identical bytes |
| RW4 | `test_magic_header` | 28-byte magic, ftype `MODEL`, objCount 1, sectionCount 3, `pSectionInfo` 0xF0, `pBufferData` 0x138, bufSize 80 |
| RW4 | `test_manifest_types` | manifest offsets + the 3 type codes, named `BaseResource`/`Raster`/`Mesh` |
| RW4 | `test_section_table` | the three 24-byte section-info records: type code, size, data address |
| RW4 | `test_base_resource_addressing` | the 0x10030 section's instance/group/type triple (the indirection `pBufferData` + pData) |
| RW4 | `test_texture_sample` | 4×2 raster, format code, 8 texels |
| RW4 | `test_model_sample` | 4 vertices, 6 u16 indices `[0,1,2,0,2,3]` |
| RW4 | `test_tool_output` | CLI run as subprocess; asserts on the printed structural-summary lines |
| GMDL | `test_parse_matches_file` | the walk-to-end contract: `finalOffset` == file size 1266 |
| GMDL | `test_semantic_snapshot` | ~30 semantic fields (version 8, refs, bbox, 153×16-bit index buffer, descriptor elements, 50-vertex buffer, materialID, counts) against an inline expected dict |
| GMDL | `test_tool_inspect` | CLI `inspect` run as subprocess; asserts on printed lines including `MATCH` |

The test style is uniform and deliberate: every test compares **parsed structures** —
dicts of semantic fields — against inline expected dicts, *never raw bytes*. On mismatch,
the failure prints a compact expected-vs-actual diff (per-field `path: expected X got Y`,
recursing into nested dicts), so a broken field shows up as one line, not a byte dump.
Tests that exercise the CLI (`test_deterministic_extraction`, `test_tool_output`,
`test_tool_inspect`) run the committed tools as subprocesses and assert on their printed
lines — the same surface a later C++ port will be diffed against.

The suite is green: `python3 -m unittest discover -s tests -t .` reports
`Ran 15 tests in 0.258s` / `OK` — 15/15 passing.

## Real-asset differential mode (opt-in)

The synthetic suite proves the tools against data they generated; it cannot prove they
still agree with the real pipeline. `tests/diff_real.py` (117 lines) closes that gap
without crossing the legal line:

```
SPORE/ (git-ignored GOG install)
  |  dbpf.py: extract ONE known record
  v
/tmp/opencode/spore/out/real_gmdl_1006.bin   (git-ignored)
  |  gmdl.py: parse
  v
semantic fields  <-->  tests/expected/real_gmdl_1006.json   (committed)
```

- **No `SPORE/`** → prints a clear message and exits 0. On a fresh checkout or in CI the
  differential is a no-op; the synthetic suite is what runs there.
- **Record lookup** → it finds one small known record by (typeID, group, instance):
  `Spore_Content.package`, GMDL type `0x00e6bce5`, 80 bytes, index 1006. If the record is
  no longer present (content changed upstream), it exits non-zero with guidance; if the
  index merely shifted, it notes the drift and continues.
- **Compare** → it parses the extracted blob with the committed tools and compares the
  semantic fields against the committed expectation file, printing the same
  expected-vs-actual diff on mismatch (exit 1).
- **`--record`** → re-records the expectation from a known-good local run.

The expectation file (41 lines of JSON) stores semantic fields **only** — type IDs,
sizes, counts, bounding values rounded to 4 decimals — never asset bytes, so it is safe
to commit. What it anchors is a degenerate v8 GMDL: `version=8`, `refCount=0`,
`meshCount=0`, empty index/vertex/material lists, bbox (0.1676, 0.4499, −0.6402) to
(0.1798, 0.4499, 16.4433), radius 16.4503, `unknownKey [0, 0xFFFFFFFF, 0]`, and
`parseMatchesFile: true` at exactly 80 bytes. This is the compromise that lets the
project keep a real-data anchor in CI without committing a single proprietary byte:
the anchor is the **shape** of the record, not its content.

## Why this mattered before deeper RE work

Everything that followed the evening of 09-20 ran against a moving target: the vtable
pass of 09-21 ([chapter 006](006-vtable-detection.md)) rewrote how class structure is
read from the binary, the observatory added a second consumer of the same environment,
and the C++ ports to come will re-implement these parsers from the Python reference. Each
of those workstreams could have silently broken a parser — a shifted offset in the GMDL
walk, a retokenized QFS stream, a dropped section in the RW4 table — and the 15-test
suite is the thing that would catch it in seconds, on any machine, from a clean checkout.
That is the whole of the value: it converts "we believe the parsers are correct" into a
claim that fails loudly the moment it stops being true, before any deeper RE result is
built on top of it.
